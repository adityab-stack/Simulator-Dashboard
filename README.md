# Snitch Control Room — V1.1

Static, filterable sales/inventory dashboard. No backend server — everything runs
client-side against `data/data.json`. GitHub Pages serves it for free.

## How it works

```
Google Sheet  --(n8n, nightly)-->  data/data.json  --(git push)-->  GitHub Pages
```

1. **n8n** pulls your Google Sheet on a schedule (e.g. 2am daily).
2. It writes/overwrites `data/data.json` in this exact shape (see below).
3. n8n commits + pushes that file to this repo (GitHub node, or a simple
   `git commit && git push` in an Execute Command node).
4. GitHub Pages redeploys automatically within ~1 minute. No server, no downtime.

## `data/data.json` shape

```json
{
  "generated_at": "2026-08-18T02:00:00",
  "sales":     [ { "month":"2026-08", "channel":"Shopify", "l1":"snitch", "cat":"shirts",
                   "m1":"cotton", "m2":"stripes", "m3":null,
                   "gross_sales":123456, "mrp_value":150000, "qty":80, "cogs_sold":45000 }, ... ],
  "inventory": [ { "month":"2026-08", "l1":"snitch", "cat":"shirts", "m1":"cotton", "m2":"stripes", "m3":null,
                   "mp_qty":0, "online_qty":500, "offline_qty":200, "total_qty":700, "total_value":900000 }, ... ],
  "targets":   [ { "l1":"snitch", "cat":"shirts", "month":"2026-08", "target":2000 }, ... ]
}
```

Right now `build_data.py` generates this from the Excel export you gave me —
swap that step for n8n reading the Google Sheet directly and writing the same
JSON keys, and the dashboard needs zero changes.

## Running it locally in VS Code

1. **Install Python** if you don't have it (3.9+), and open this folder in VS Code
   (`File → Open Folder`).
2. **Install the two packages it needs** — open the VS Code terminal
   (`` Ctrl+` ``) and run:
   ```bash
   pip install openpyxl requests
   ```
3. **Pull fresh data.** Two options:
   - If the Google Sheet is shared as "Anyone with the link can view":
     ```bash
     python build_data.py
     ```
     This downloads the whole sheet straight from the link you gave me and rebuilds `data/data.json`.
   - If it's private, export it yourself (File → Download → Microsoft Excel)
     as `Automation_Data.xlsx` in this same folder, then run:
     ```bash
     python build_data.py --local
     ```
4. **View the dashboard.** Don't just double-click `index.html` — browsers block
   `fetch()` calls to local files that way, and the charts won't load. Instead, run:
   ```bash
   python -m http.server 8000
   ```
   then open **http://localhost:8000** in your browser. (Or install the
   **Live Server** extension in VS Code and click "Go Live" at the bottom right —
   same effect, one click.)

Whenever you re-run `build_data.py`, just refresh the browser tab — no restart needed.

## Hosting on GitHub Pages

```bash
git init
git add .
git commit -m "V1.1 dashboard"
git remote add origin <your repo url>
git push -u origin main
```

Then in the repo: **Settings → Pages → Deploy from branch → main → / (root)**.
Your site goes live at `https://<you>.github.io/<repo>/`.

## Filtering

All filters (Channel, L1, Category, Meta1/2/3) run in-browser against the JSON —
instant, no reload, works offline once loaded. KPIs, charts, and the top-categories
table all recompute live from whatever subset is selected.

## What V1.1 replicates from your Excel, exactly

- **Closing(leaf, month)** = the latest dated inventory snapshot *within* that
  month, for that exact L1×Cat×Meta1×Meta2×Meta3 combo — not a sum of daily
  snapshots, not an average. Matches your `Overall` tab's
  `SUMIFS(qty, key, MAXIFS(date, date within month))` formula.
- **Opening(leaf, month)** = Closing of the previous month, same logic.
- Rollups (L1, L1×Cat, Meta1, etc.) sum the **leaf-level** Opening/Closing
  across every leaf in that group — never re-derived at the rolled-up level,
  to avoid double-counting or drift.
- **Channel filter on inventory**: Inv Data 2 splits stock into MP/Online/Offline
  qty & value. Mapped as `Shopify→Online`, `Marketplace→MP`, `Offline→Offline`.
  Flag me if this mapping is wrong.
- **Data cleaning applied**: ~122 blank/junk rows in Inv Data 2 (missing L1 or
  Category — likely stray subtotal rows) are filtered out in `build_data.py`
  before they can pollute rollups.
- **Target, Inwards, Plan Closing** all render as `—`, never a guessed number,
  until those sources are wired in.
